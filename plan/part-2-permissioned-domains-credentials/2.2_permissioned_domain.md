# Phase 2.2 — Permissioned Domain

Part 2 (Loaded: Permissioned Domains + Credentials) · Spec: XLS-80 Permissioned Domains.

## Objective
Create a permissioned domain that accepts a credential, and verify **standalone** that a
subject holding an accepted matching credential is a domain member while a non-holder is not.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase builds its own issuer, subject,
credential, and domain, and proves membership by itself — it does **not** defer the proof to
phase 2.3.

## Key correction (design)
`PermissionedDomainSet.AcceptedCredentials` is a list of **wrapped** entries:
`[{ Credential: { Issuer, CredentialType } }]`. The flat `{ Issuer, CredentialType }` form
fails xrpl@5.1.0 validation. Membership = holding an **accepted** credential matching one
entry in the list.

## Preconditions this phase builds
1. Fund `issuer`, `member`, `outsider`.
2. Issue and accept a credential for `member` (inline: `CredentialCreate` +
   `CredentialAccept`, reproducing the 2.1 procedure).

## Transaction steps (exact fields)
1. **PermissionedDomainSet**, `Account=issuer` (domain owner).
   - `AcceptedCredentials`: `[{ Credential: { Issuer, CredentialType } }]` (the member's
     issuer + credential-type hex).
   - Capture `DomainID` from metadata.
2. **Standalone membership proof (no other phase):**
   - Read the `PermissionedDomain` object; assert its accepted list contains
     `{ Issuer, CredentialType }`.
   - Read the `member`'s `Credential` object; assert it is **accepted** and matches that
     issuer + type.
   - Confirm `outsider` holds no such accepted credential.

## Expected results and assertions
- `PermissionedDomainSet` → `tesSUCCESS`; a `PermissionedDomain` object exists with the
  wrapped accepted-credentials list.
- `member` qualifies (accepted matching credential); `outsider` does not.

## Explorer verification
Record `PermissionedDomainSet` hash and the `PermissionedDomain` object contents.

## Friction to capture
- Was the `{ Credential: { ... } }` wrapper documented, or discovered by a validation error?
- Could you read domain membership directly, or only infer it from a gated action?
