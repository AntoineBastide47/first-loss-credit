# Phase 2.3 — Gated Private Vault

Part 2 (Loaded: Permissioned Domains + Credentials) · Spec: XLS-65 + XLS-70 + XLS-80.

## Objective
Gate **vault depositors and share holders** by credential. A credentialed member deposits
successfully; a non-member is rejected with `tecNO_AUTH`.

## Scope correction (important)
A private vault gates **depositors and share ownership only**. `LoanSet` has **no** `DomainID`
or credential field, so the protocol does **not** gate loan *borrowers*. Borrower eligibility
is **application logic** unless another enabled amendment enforces it. Do not claim protocol
borrower gating.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase builds its own issuer,
credentialed member, outsider, domain, and private vault by composing the shared `lib/` builders
(it references no other phase and depends on no future phase).

## Preconditions this phase builds
1. Fund `issuer`, `member`, `outsider`, `vaultOwner`.
2. Issue + accept a credential for `member`; create a permissioned domain accepting it
   (via the shared credential/domain builders). Capture `DomainID`.

## Transaction steps (exact fields)
1. **VaultCreate** (`tt=65`), `Account=vaultOwner`.
   - `Asset`: `{ currency: "XRP" }` (the bare string `"XRP"` fails xrpl@5.1.0; MPT asset is Part 3).
   - `Flags`: `tfVaultPrivate` (`0x00010000`).
   - `DomainID`: the domain from preconditions.
   - Capture `VaultID`, `ShareMPTID`.
2. **VaultDeposit** (`tt=68`), `Account=member`, `VaultID`, `Amount` → expect success.
3. **VaultDeposit** (`tt=68`), `Account=outsider`, `VaultID`, `Amount` → expect rejection.

## Expected results and assertions
- Step 1 `tesSUCCESS`; vault carries the private flag and `DomainID`.
- Step 2 (`member`) → `tesSUCCESS`; `member` receives share MPT; `AssetsTotal`/
  `AssetsAvailable` rise.
- Step 3 (`outsider`) → **`tecNO_AUTH`**. Ensure the outsider is well funded so the failure
  is authorization, not balance.

## Explorer verification
Record `VaultCreate` (private + `DomainID`), the successful member deposit, and the rejected
outsider deposit.

## Precision and timing rules
- An expired or unaccepted credential must also fail authorization; add that as a control if
  time allows.

## Friction to capture
- Was it clear that private-vault gating covers depositors but **not** borrowers?
- Did the docs explain how to gate borrowers (application layer) when the protocol does not?

## xrpl.js references
`VaultCreate` (flags, `DomainID`), `VaultDeposit` models.

## XLS references
XLS-65 §3.2 (`tfVaultPrivate`, `DomainID`); XLS-70 Credentials; XLS-80 Permissioned Domains.
