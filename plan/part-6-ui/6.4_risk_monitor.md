# Phase 6.4 — Risk Monitor

Part 6 (UI) · Spec surface: XLS-66 (impairment, default, first-loss waterfall) · Composes `6.0`.

## Objective
A read-only dashboard that shows portfolio health and the first-loss waterfall: how junior cover
absorbs a default before senior lenders take a realized loss. The investor-facing view.

## Independence contract
Inputs: a vault + broker (and optionally loan) id set from the scenario config or paste fields.
Read-only. References no other UI phase and no backend phase; depends on no future phase; reads
no other phase's runtime state.

## Inputs this phase takes
- `VaultID`, `LoanBrokerID`, and 0+ `LoanID`s (config or paste). No wallet required (read-only).

## Views
| View | Purpose |
|------|---------|
| Vault health | `AssetsTotal`, `AssetsAvailable`, `LossUnrealized`, derived utilisation + share price |
| Cover | `CoverAvailable` vs required minimum; `CoverRateLiquidation` |
| Loan table | each loan's status (current / impaired `lsfLoanImpaired` / defaulted `lsfLoanDefault`), due date, outstanding |
| First-loss waterfall | a stacked bar: senior principal, junior cover, and (on default) covered vs realized loss |

## Components and data flow
- Poll `readVault` + `readBroker` + each `readLoan` on a timer; derive everything in `6.0`.
- Waterfall: while healthy, show senior assets and junior cover layers. On impairment, show the
  `LossUnrealized` band (share price drops). On default, show `DefaultCovered` (absorbed by
  junior) vs realized loss (`AssetsTotal` drop) — the conservation `DefaultAmount = covered +
  loss` is drawn to scale.
- Status badges derive from loan `Flags` (`lsfLoanImpaired`, `lsfLoanDefault`) and
  `NextPaymentDueDate` vs current ledger time (overdue / within grace / past grace).

## Build steps
1. Route `/risk`; read all ids; render the four views from derived getters.
2. Waterfall component driven purely by reads (impaired → default transitions appear as the chain
   state changes; no writes here).
3. Timeline ribbon per loan: origination → due → grace end, with the current ledger time marker.

## Acceptance checks
- With a healthy vault, utilisation and share price match a fresh `vault_info`.
- When a loan is impaired elsewhere, `LossUnrealized` appears and share price drops on-screen.
- After a default elsewhere, the waterfall shows cover absorbing the first loss and the residual
  as a senior loss; the numbers reconcile to `DefaultAmount = DefaultCovered + realized loss`.

## Verification
Every figure traces to a ledger read; a "view source" affordance shows the raw `vault_info` /
broker / loan JSON behind each panel.

## Precision / UX rules
- High-precision fields formatted from strings; the waterfall scales by BigInt drops.
- Treat absent `CoverAvailable`/`DebtTotal` as `0` (XRPL omits zero-valued fields after default).
- Read-only: no action buttons; this screen never signs.

## Friction to capture
- Did the waterfall make the junior→senior loss order obvious to a non-expert?
- Were impair/default states legible from the ledger flags alone?
