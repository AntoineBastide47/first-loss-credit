# Phase 6.1 — Vault Lender Console

Part 6 (UI) · Spec surface: XLS-65 · Composes `6.0` + `lib/`.

## Objective
A senior lender's screen: deposit XRP into a vault, see derived share value and yield, and
redeem shares above par. Make "yield is derived, not stored" visible.

## Independence contract
Inputs: a `VaultID` (from the scenario config or a paste field) and a connected wallet. It
references no other UI phase and no backend phase, depends on no future phase, and reads no
other phase's runtime state.

## Inputs this phase takes
- `VaultID` (required) and the vault's `ShareMPTID` (read from `vault_info`).
- Connected wallet = the lender (or demo wallet).

## Views
| View | Purpose |
|------|---------|
| Position | lender's shares, current redeemable value, gain vs cost basis (kept client-side) |
| Vault state | `AssetsTotal`, `AssetsAvailable`, `OutstandingShares`, derived share price, utilisation |
| Actions | Deposit (XRP) · Redeem (all or part of shares) |

## Components and data flow
- Poll `readVault(VaultID)` + `shareBalance(lender, ShareMPTID)` on a timer and after each write.
- `sharePrice = AssetsTotal / OutstandingShares`; redeemable = `shares * (AssetsTotal -
  LossUnrealized) / OutstandingShares`. Show `LossUnrealized` when non-zero (ties to `6.4`).
- Deposit: `VaultDeposit { VaultID, Amount: <drops string> }`, signed by the lender.
- Redeem: `VaultWithdraw { VaultID, Amount: { mpt_issuance_id: ShareMPTID, value: <shares> } }`
  to redeem shares for full value; an XRP-amount withdraw (assets) is a separate, clearly
  labelled option (it leaves yield behind).

## Build steps
1. Route `/lender`; read the vault; render the three views from derived getters in `6.0`.
2. Deposit form (XRP input → drops) → `TxButton` signs `VaultDeposit`, waits validated, refreshes.
3. Redeem control with an all/partial toggle; default is the **share-amount** redeem.
4. Cost-basis: store the lender's deposited drops locally; show gain = redeemable − basis.

## Acceptance checks
- After a deposit of `D`, `AssetsTotal` and the lender's shares both increase by `D` (scale 0).
- After a loan cycle raises `AssetsTotal` elsewhere, the screen's share price rises with no new
  deposit — proving derived yield.
- A full share redeem pays out **more** than the deposit when yield exists; the UI shows the gain
  and the `VaultWithdraw` explorer link.

## Verification
Explorer links for each `VaultDeposit` / `VaultWithdraw`; the view matches a fresh `vault_info`.

## Precision / UX rules
- Format amounts from strings/BigInt; never `Number()` money. Share price shown to a fixed,
  honest precision with a "derived" tag.
- Disable Redeem when `AssetsAvailable` < requested asset value and explain it (liquidity, not
  balance) — the same cause as guardrail case A.

## Friction to capture
- Was "share value rises without a stored field" clear to a first-time viewer?
- Was the asset-amount vs share-amount withdraw distinction obvious in the UI?
