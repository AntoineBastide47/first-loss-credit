# Phase 6.2 — Broker Cover Console

Part 6 (UI) · Spec surface: XLS-66 (first-loss cover) · Composes `6.0` + `lib/`.

## Objective
The junior provider's screen: post and withdraw first-loss cover, and see the cover-minimum
guardrail as a live gauge, so the "junior absorbs first loss" role is tangible.

## Independence contract
Inputs: a `LoanBrokerID` (scenario config or paste field) and a connected wallet = the broker
owner. References no other UI phase and no backend phase; depends on no future phase; reads no
other phase's runtime state.

## Inputs this phase takes
- `LoanBrokerID` (required); the broker owner's wallet (only `Vault.Owner`/broker owner may act).

## Views
| View | Purpose |
|------|---------|
| Cover gauge | `CoverAvailable` vs required minimum = `DebtTotal * CoverRateMinimum/100000` |
| Parameters | `CoverRateMinimum`, `CoverRateLiquidation`, `ManagementFeeRate`, `DebtTotal`, `DebtMaximum` |
| Actions | Deposit cover · Withdraw cover |

## Components and data flow
- Poll `readBroker(LoanBrokerID)`; derive `requiredMin` and `coverRatio`; render a gauge with a
  red zone below the minimum.
- Deposit: `LoanBrokerCoverDeposit { LoanBrokerID, Amount }`.
- Withdraw: `LoanBrokerCoverWithdraw { LoanBrokerID, Amount }`. Before submit, compute whether the
  amount would drop cover below `requiredMin`; if so, warn that it will be rejected
  (`tecINSUFFICIENT_FUNDS`) and still let the user try (to demonstrate the guardrail), showing the
  exact code and explorer link on return.

## Build steps
1. Route `/broker`; read the broker; render gauge + parameters.
2. Deposit form → `TxButton` signs `LoanBrokerCoverDeposit`, waits validated, refreshes gauge.
3. Withdraw form with the pre-check warning; on a rejected attempt, surface the `tec*` badge
   (`6.5`) and confirm `CoverAvailable` is unchanged.

## Acceptance checks
- Depositing `C` raises `CoverAvailable` by `C`.
- A withdraw that would breach the minimum returns `tecINSUFFICIENT_FUNDS`, cover unchanged; a
  smaller withdraw that stays ≥ minimum succeeds. Gauge reflects both.

## Verification
Explorer links for each cover tx (including the rejected one); gauge matches a fresh broker read.

## Precision / UX rules
- Cover rates are 1/10 bps (100% = 100000); show them as percentages but store/send integers.
- `tecINSUFFICIENT_FUNDS` here means a **cover-ratio** breach, not a balance shortfall — label it
  that way (see `6.5`).

## Friction to capture
- Did the gauge make the minimum-cover constraint understandable before trying a withdraw?
- Was the 1/10 bps rate unit clear in the form?

## references
