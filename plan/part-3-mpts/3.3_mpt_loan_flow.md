# Phase 3.3 — MPT Loan Flow

Part 3 (Loaded: MPTs) · Spec: XLS-65 + XLS-66 + XLS-33.

## Objective
Run a full loan (originate + repay) in an MPT-denominated vault and prove the payment
rounding rule: the high-precision periodic payment must round **up** to a whole MPT base
unit.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase issues its own MPT, builds an
MPT vault, a broker with MPT cover, and one loan by composing the shared `lib/` builders (not by
importing 3.1/3.2). It references no other phase and depends on no future phase.

## Preconditions this phase builds
1. Fund `issuer`, `lender`, `owner` (vault + broker owner), `borrower`.
2. Transferable MPT; lender and borrower authorized; MPT minted to the lender.
3. MPT vault funded by the lender; broker on that vault with MPT cover
   (`LoanBrokerCoverDeposit` in MPT units).

## Transaction steps (exact fields)
1. **LoanSet** (`tt=80`), dual-signed via the shared `lib/` loan builder (`originateLoan`).
   - `PrincipalRequested` is an **XRPLNumber string** (e.g. `"1000"`), **not** an MPT amount
     object. Only `LoanPay.Amount` uses `{ mpt_issuance_id, value }`.
   - Terms: short `PaymentInterval`, `PaymentTotal`, an `InterestRate`.
2. **LoanPay** (`tt=84`), `Account=borrower`, `LoanID`, `Amount` =
   `{ mpt_issuance_id, value }` where `value =
   roundUpToAssetUnit(PeriodicPayment + LoanServiceFee, MPT)`.

## Expected results and assertions
- Origination moves MPT principal (minus origination fee) to the borrower and books interest
  to `AssetsTotal` in MPT units; `DebtTotal` rises.
- A payment computed by truncating `PeriodicPayment` **down** falls short →
  **`tecINSUFFICIENT_PAYMENT`** (demonstrate), then the rounded-up amount → `tesSUCCESS`.
- Loan accounting fields (`PeriodicPayment`, `TotalValueOutstanding`) remain high-precision
  even though MPT balances are integer base units. Assert both representations.

## Explorer verification
Record `LoanSet`, the short `LoanPay`, and the successful rounded `LoanPay`.

## Precision and timing rules
- `Loan.PeriodicPayment` is high-precision; the **paid MPT amount** must be a whole MPT base
  unit, rounded **up**. This is the central lesson of this phase.
- Keep MPT `AssetScale` (token precision) distinct from the loan's internal `LoanScale`.
- `PrincipalRequested` is a string; `LoanPay.Amount` is an MPT amount object. Do not mix them.

## Friction to capture

- Did the SDK help convert `PeriodicPayment` to a payable MPT amount, or was it manual?
- Was the `PrincipalRequested` string vs `LoanPay.Amount` object split documented?
