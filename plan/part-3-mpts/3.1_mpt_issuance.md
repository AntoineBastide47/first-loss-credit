# Phase 3.1 — MPT Issuance

Part 3 (Loaded: MPTs) · Spec: XLS-33 Multi-Purpose Tokens.

## Objective
Issue an MPT suitable to be a vault asset and to authorize holders, including the two-step
authorization path when the issuance requires auth.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase creates its own issuer and
holders and ends with an authorized MPT it does not hand to another phase.

## Requirements (design)
- The issuance must set **`tfMPTCanTransfer`** so the token can move between the vault
  pseudo-account, lenders, and borrowers.
- If **`tfMPTRequireAuth`** is set, holder creation and issuer authorization are **two
  separate `MPTokenAuthorize` steps** (holder opts in; issuer authorizes the holder).
- Verified flag hex (xrpl@5.1.0): `tfMPTCanTransfer` `0x20`, `tfMPTRequireAuth` `0x04`,
  `tfMPTCanEscrow` `0x08`.

## Preconditions this phase builds
1. Fund `issuer`, `holderA`, `holderB`.

## Transaction steps (exact fields)
1. **MPTokenIssuanceCreate**, `Account=issuer`.
   - `AssetScale`: the MPT's own decimal scale (keep distinct from any vault share scale).
   - `MaximumAmount`: supply cap (optional).
   - `TransferFee`: 0 unless a fee is wanted.
   - `Flags`: `tfMPTCanTransfer` (+ `tfMPTRequireAuth` if gating holders, + `tfMPTCanEscrow`
     if this MPT will also be escrow collateral in Part 4).
   - `MPTokenMetadata`: hex (optional).
   - Capture `MPTokenIssuanceID`.
2. **MPTokenAuthorize** (holder opt-in), `Account=holderA`, `MPTokenIssuanceID`.
3. **MPTokenAuthorize** (issuer authorize), `Account=issuer`, `MPTokenIssuanceID`,
   `Holder=holderA` — required only when `tfMPTRequireAuth` is set.

## Expected results and assertions
- Issuance `tesSUCCESS`; `MPTokenIssuance` object exists with the chosen flags and
  `AssetScale`.
- With `tfMPTRequireAuth`: a holder cannot hold a positive balance until **both** step 2 and
  step 3 complete. Assert the ordering.
- Negative control: a transfer to an unauthorized holder fails when auth is required.

## Explorer verification
Record `MPTokenIssuanceCreate` and each `MPTokenAuthorize`; show the issuance flags.

## Precision and timing rules
- `AssetScale` is the MPT's own scale. Keep it **separate** from the vault share `Scale`
  (Part 3.2). Mixing them is a likely bug.

## Friction to capture
- Was the two-step auth (holder opt-in + issuer authorize) obvious, or did one direction
  surprise you?
- Were the `tfMPT*` flags and their hex values easy to find?
