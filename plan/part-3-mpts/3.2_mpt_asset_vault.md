# Phase 3.2 — MPT-Asset Vault

Part 3 (Loaded: MPTs) · Spec: XLS-65 + XLS-33.

## Objective
Create a Single Asset Vault whose asset is an MPT, deposit and withdraw the MPT, and confirm
the forced-scale behavior for MPT vaults.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase issues its own MPT (via the shared
MPT-issuance builder in `lib/`, not by importing 3.1), authorizes the lender, and builds the
vault. It references no other phase and depends on no future phase.

## Requirements (design)
- **Vault asset shape:** `Asset: { mpt_issuance_id: issuanceId }` — **no `value`** (asset
  identity only). The deposit/withdraw `Amount` fields **do** carry `value`.
- **Omit `Scale` from `VaultCreate`.** Do **not** send `Scale: 0`; the field must be
  **absent**. The resulting vault `Scale` must read as **0**.
- The vault pseudo-account must be able to hold the MPT, so the MPT must be transferable
  (`tfMPTCanTransfer`) and, if `tfMPTRequireAuth` is set, the pseudo-account path must be
  authorized per the spec's handling.

## Preconditions this phase builds
1. Fund `issuer`, `lender`, `owner` (vault owner).
2. Issue a transferable MPT; authorize `lender` to hold it; mint some to `lender`.

## Transaction steps (exact fields)
1. **VaultCreate** (`tt=65`), `Account=owner`.
   - `Asset`: `{ mpt_issuance_id: issuanceId }` (no `value`).
   - **No `Scale` field.**
   - Capture `VaultID`, `ShareMPTID`.
2. **VaultDeposit** (`tt=68`), `Account=lender`, `VaultID`, `Amount` =
   `{ mpt_issuance_id, value }`.
3. **VaultWithdraw** (`tt=69`), `Account=lender`, `VaultID`, `Amount` = MPT amount or share
   MPT amount.

## Expected results and assertions
- `VaultCreate` `tesSUCCESS`; read the vault and assert **`Scale == 0`**.
- Deposit raises `AssetsTotal`/`AssetsAvailable` in MPT units and mints share MPT to the
  lender (`MPToken.MPTAmount` per the initial/subsequent share rule with `10^0 = 1`).
- Withdraw returns MPT to the lender.
- Negative control: `VaultCreate` **with** an explicit `Scale` on an MPT asset is rejected by
  xrpl@5.1.0 at **client-side validation** (it is **not** normalized), so there is normally
  **no transaction hash**. Record the validation error, not a ledger result.

## Explorer verification
Record `VaultCreate`, the MPT deposit and withdraw; show vault `Scale == 0` and MPT balances.

## Precision and timing rules
- Vault share `Scale` (0 here) is **separate** from the MPT's own `AssetScale`. Track both.
- MPT amounts are integers in base units; conversions use the MPT `AssetScale`.

## Friction to capture
- Was "omit `Scale`, do not send 0" documented, or discovered by a rejected transaction?
- How did the MPT `Asset` (`{ mpt_issuance_id }`, no value) differ from the deposit `Amount`
  (`{ mpt_issuance_id, value }`)?

## xrpl.js references
`VaultCreate` (`Asset` = `{ mpt_issuance_id }`), `VaultDeposit`, `VaultWithdraw`; MPT `Amount`
typing.

## XLS references
XLS-65 §3.2 (`Scale` forced to 0 / rejected for MPT, §3.2.5.2), §3.1.7 (share math);
XLS-33 (MPT amounts).
