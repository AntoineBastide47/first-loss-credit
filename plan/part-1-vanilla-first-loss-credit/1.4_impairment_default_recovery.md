# Phase 1.4 — Impairment, Default, and Recovery

Part 1 (Vanilla) · Project: first-loss-credit · Spec: merged XLS-66.

## Objective
Drive a loan through impairment and default, and prove first-loss recovery: cover is
liquidated to the vault and the residual becomes a vault loss. This is the richest,
most-novel part of XLS-66.

## Independence contract
Inputs: none. Outputs consumed downstream: none. This phase builds its own vault, broker
(with cover), borrower, and one loan, then lets it go overdue.

## Preconditions this phase builds
1. Fund `owner` (vault + broker owner), `lender`, `borrower`.
2. Vault (`Asset: { currency: "XRP" }`) funded; broker with known `CoverAvailable`,
   `CoverRateMinimum`, `CoverRateLiquidation`.
3. One loan with a **short** `PaymentInterval` and `GracePeriod` so overdue and default
   windows are reachable in event time.

## Transaction steps (exact fields)
1. **Let the loan go overdue**: advance validated ledgers until `now > NextPaymentDueDate`
   (do not pay). Use `lib.waitLedgers`.
2. **LoanManage impair** (`tt=82`), `Account=owner`, `LoanID`, `Flags=tfLoanImpair`
   (`0x00020000`).
3. Advance ledgers until one validated ledger is **strictly beyond**
   `NextPaymentDueDate + GracePeriod`.
4. **LoanManage default** (`tt=82`), `Account=owner`, `LoanID`,
   `Flags=tfLoanDefault` (`0x00010000`).
5. Optional recovery control: **LoanManage unimpair** (`tfLoanUnimpair` `0x00040000`) or a
   qualifying `LoanPay` clears `lsfLoanImpaired` before default.

## Expected results and assertions (✅ verified live on the hackathon devnet)
- **Impair:** sets `lsfLoanImpaired` (loan `Flags & 0x00020000`); `Vault.LossUnrealized`
  increases. Verified value = **`PrincipalOutstanding`** (e.g. 40000000), not
  `TotalValueOutstanding` (40000077); accrued interest is not included in the unrealized loss
  here. Withdraw redemption then uses `(AssetsTotal - LossUnrealized) / SharesTotal`, so share
  value drops.
- **Default:** sets `lsfLoanDefault`. **Formula verified:**
  `DefaultCovered = min(DebtTotal * CoverRateMinimum * CoverRateLiquidation, DefaultAmount,
  CoverAvailable)` — observed `min(40*0.1*1.0, 40, 10) = 4 XRP`. Full state change verified:
  - `LoanBroker.CoverAvailable -= DefaultCovered` (cover pool → vault): 10 → 6 XRP.
  - `Vault.AssetsAvailable += DefaultCovered` (cover cash arrives): 60 → 64 XRP.
  - `Vault.AssetsTotal -= (DefaultAmount - DefaultCovered)` (residual realized loss):
    100 → 64 XRP (36 XRP loss).
  - `LoanBroker.DebtTotal -= DefaultAmount`: 40 → 0 XRP.
  - `Vault.LossUnrealized` is **reversed to 0** (loss moves from unrealized to realized).
  - **Conservation verified:** `DefaultAmount == DefaultCovered + realized loss`.
  - Note: after default `CoverAvailable`/`DebtTotal` may read as **absent** (XRPL omits
    zero-valued fields) — treat a missing field as `0`.
- **Timing negatives (controls, both verified `tecTOO_SOON`):** impair before the loan is
  overdue; default before one validated ledger strictly beyond `NextPaymentDueDate +
  GracePeriod`. Minimum windows: `PaymentInterval >= 60 s`, `GracePeriod >= 60 s` and
  `<= PaymentInterval`. Wait on ledger **close time** (ripple time), not ledger count.

## Explorer verification
Record `LoanManage` impair and default hashes; show `CoverAvailable`, `AssetsTotal`,
`AssetsAvailable`, `DebtTotal`, and `LossUnrealized` changes.

## Precision and timing rules
- `DefaultAmount` and the cover figures are high-precision; compare with a tolerance at the
  asset unit, not exact equality.
- Impair **after** `NextPaymentDueDate`. Default only one validated ledger **strictly
  beyond** `NextPaymentDueDate + GracePeriod`. A single close call causes a `tecTOO_SOON`
  retry loop — log it if it happens.
